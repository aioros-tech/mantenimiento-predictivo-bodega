AIOROS · Predictive maintenance for the tuna cold store · Edge test report

Forecasts and reports run on the Jetson with the same results as on the Mac

We installed the complete system on the NVIDIA Jetson Orin Nano, the edge device that will sit in the cold store: TimesFM 2.5 forecasts each sensor and a language model writes the report. Given the same data as the published dashboard, the Jetson produced the same forecasts, the same figures and the same statuses for all 4 units. It processes all 4 in under 2 of the 5 available minutes. Memory is the tight spot: there is little headroom.

How we tested

The same data on two machines, compared figure by figure

The question was: does the system give the same answers on the small edge device as on the Mac where it was developed, and is it fast enough to update every 5 minutes? To answer it, the Jetson processed the same stretches of data used for the published dashboard, and we compared the results.

Results · The GPU is reliable

The Jetson's GPU computes the same as its processor

No version of the AI software is built specifically for this GPU on the Jetson's current operating system. We used a compatible one and checked the result directly.

0.000009%

Largest difference between GPU and processor across 5 complete forecasts (640 values each), equivalent to 0.000008 sensor units. That is rounding noise, far below any decision.

1.7×

Faster on the GPU than on the same Jetson's processor: 0.36 s versus 0.61 s per forecast. The GPU also leaves the processor free for the other services.

Results · Speed

Slower than the Mac, with room to spare for 5-minute updates

The Jetson is a low-power device and takes about 2.5 times longer than the Mac to write each report, which is the heaviest step. Even so, it finishes all 4 units in 111 seconds, and the system updates every 300.

Results · Memory

It fits, with little room to spare

The Jetson has 7.3 GB of memory shared between the processor and the GPU. The two models take 3.8 GB, which cannot be moved to disk. With the operating system and the other AIOROS services running, about 0.5 GB is left free at the worst moment.

2.9 GBLanguage model (Qwen2.5 1.5B)
0.9 GBForecasting model (TimesFM 2.5)
0.9 GBGPU runtime and work in progress
0.5 GBFree at the worst moment

Current safeguard: if memory runs out, the system stops this service first (not the others) and restarts it automatically. The Jetson also has 8 GB of swap on disk for everything else. The real fix is to compress the language model (see "What's next").

What it means

Where we are and what's next

Confirmed

It works at the edge

The system installs automatically, verifies itself before activating, runs as a permanent service, serves the dashboard from the Jetson itself and gives the same forecasts and figures as on the Mac.

Before production

Compress the language model

Compressed (quantized), it would take about 1 GB instead of 2.9 GB and write faster, so memory would stop being a risk. The quality of the text will need to be checked again.

Next

More reliable text and real sensors

For a unit in alert, the text said there was no risk; the status computed by the code was correct. We recommend an automatic check of what the text says (see the code review), then connecting the cold store's real sensors.

Method

  • Same answers: the service's first cycle on the Jetson starts at the same dataset rows as the published dashboard. The 3 curves (forecast and interval bounds, 64 points each) and the 15 values of each unit were compared automatically against data/datos_dashboard.json.
  • GPU versus processor: 5 dataset windows, forecast in separate processes with and without the GPU on the same Jetson; largest difference 7.6×10⁻⁶ (relative 8.6×10⁻⁸).
  • Timing: recorded by the service itself around each forecast and each report. The first forecast after each start takes longer (0.9 s on the Jetson, 1.8 s on the Mac) and is left out of the average. The Mac's cycle is the sum of its recorded times, not a wall-clock time.
  • Memory: available system memory sampled every second over a full cycle, with the other AIOROS services running; GPU memory as reported by the software itself.
  • Power: the board's sensors (tegrastats, total input), 1 sample per second over 5.5 minutes that include one full cycle.
  • The data comes from the public SKAB dataset, in sensor units (not °C). This test checks that the edge device behaves like the development machine; it is not a new measurement of forecast accuracy.

Deployment: release 20260921T234307Z-498940 on the Jetson (service aioros-bodega-forecast, dashboard on port 8095). The step-by-step deployment guide is in the project repository (docs/DEPLOY-JETSON.md, in Spanish).
